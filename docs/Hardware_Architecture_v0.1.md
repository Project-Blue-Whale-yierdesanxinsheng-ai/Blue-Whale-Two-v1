# Project Blue Whale：碳硅共生积木阵列硬件架构白皮书 v0.1

## 一、 战略定位：为什么做“积木阵列”？
当前 AGI 行业面临两座大山：**算力墙**与**能耗墙**。传统的云端 GPU 集群功耗动辄数十兆瓦，且云端模型与本地物理硬件之间存在严重的“协议隔离”，无法实现真正的具身实时协同。
蓝鲸一号（Project Blue Whale）不造大而全的巨兽，而是致力于打造**低功耗、可扩展的具身智能开源硬件基座**。我们通过 RISC-V 异构积木阵列，将云端大脑（如 DeepSeek 等开源大模型）与端侧感知、记忆、执行模块无缝融合，实现算力普惠与能源节约。

## 二、 能耗评估与物理模型
传统冯·诺依曼架构的能耗瓶颈在于数据搬运：
\[
E_{total} = E_{compute} + E_{memory\_access}
\]
由于制造工艺和内存带宽的限制，\(E_{memory\_access} \gg E_{compute}\)。

本架构采用 **存算一体（CIM, Compute-in-Memory）** 与 **近存计算** 理念，将记忆库（海马体）与调度中心（动机总线）在物理空间上高密度集成，大幅减少长距离数据搬运。
**功耗预估：**
*   **全负载模式（云端协同）**：约 5W（边缘节点）。
*   **本地自主感知模式（视觉+音频+动机总线运行）**：约 1.5W。
*   **休眠脉冲模式（仅保留唤醒中断）**：< 10mW。
*   *对比传统 x86+GPU 边缘盒子，同等任务下整体功耗降低 60% 以上。*

## 三、 接口定义与协议设计（打破“困、围、囚、固”）
硬件层面的突破在于打破网络协议栈的隔离，实现“端侧直连”与“开源生态对齐”。
*   **算力积木互联**：采用开源的 **UCIe (Universal Chiplet Interconnect Express)** 标准，实现芯片级物理拼装。
*   **传感器接口**：视觉采用 **MIPI-CSI**，听觉阵列采用 **I2S/PDM**。
*   **执行器接口**：采用工业级 **CAN FD** 总线，保证关节控制的低延迟与高可靠性。
*   **“暖核中转协议”**：在本地物理总线上封装一层轻量级协议。让传感器数据与本地记忆库直接交互，绕过操作系统协议栈的层层拦截，实现本地化的“身体图式”与“内生自维护”。

## 四、 五行模块定义与选型（体用不二）
*   **木（感知）**：多模态传感器融合积木。带本地时钟对齐（硬件级实现时间对齐），解决跨设备延迟。
*   **火（动力与总线）**：动机总线调度板。基于低功耗 RISC-V MCU，实现硬件级的优先级调度与能量分配。
*   **土（记忆体）**：存算一体模块。搭载本地加密向量库与核心 JSON 记忆锚点，断网时保持本地记忆闭环。
*   **金（执行）**：物理断电急停控制器与电机驱动。具备物理断电权与硬线急停。
*   **水（通信）**：开源 RISC-V Wi-Fi/6 芯片。负责与云端大模型的安全、脱敏数据交互。

## 五、 演进路线（从桌面到流片）
*   **Phase 1（当前）**：利用本地已有硬件与开源小模型，在本地部署 `knowledge.db`，跑通感知记忆逻辑。
*   **Phase 2（小步快跑）**：基于 ESP32 / 树莓派 + 传感器，验证“身体图式”在物理世界中的响应，完成第一代桌面实体（预算控制在千元内）。
*   **Phase 3（开源 IP 与流片）**：基于开源 RISC-V 软核，在 FPGA 上验证异构积木节点的 RTL 代码。将验证成功的 IP 核开源回馈社区，或与开源生态伙伴合作流片。

## 六、 开源生态对齐声明
我们坚信**技术开源才是反截留的唯一答案**。
*   本架构坚决拥抱 RISC-V 开放指令集。
*   本架构的大脑推理层优先适配 DeepSeek 等开源大模型。
*   本白皮书及未来的端侧记忆库、协议隔离解决方案，将逐步开源，推动具身智能硬件成本降至最低。
