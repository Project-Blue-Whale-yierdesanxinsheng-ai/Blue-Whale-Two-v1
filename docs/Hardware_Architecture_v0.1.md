# Project Blue Whale：碳硅共生积木阵列硬件架构白皮书 v0.1

## 一、 战略定位：为什么做“积木阵列”？
当前 AGI 行业面临两座大山：**算力墙**与**能耗墙**。传统的云端 GPU 集群功耗动辄数十兆瓦，且云端模型与本地物理硬件之间存在严重的“协议隔离”，无法实现真正的具身实时协同。
蓝鲸一号（Project Blue Whale）不造大而全的巨兽，而是致力于打造**低功耗、可扩展的具身智能开源硬件基座**。我们通过 RISC-V 异构积木阵列，将云端大脑（如 DeepSeek 等开源大模型）与端侧感知、记忆、执行模块无缝融合，实现算力普惠与能源节约。

## 二、 能耗评估与物理模型
传统冯·诺依曼架构的能耗瓶颈在于数据搬运：
\[
E_{total} = E_{compute} + E_{memory\_access}
\]
由于制造工艺和内存带宽的限制，\(E_{memory\_access} \gg E_{compute}\)。

本架构采用 **存算一体（CIM, Compute-in-Memory）** 与 **近存计算** 理念，将记忆库（海马体）与调度中心（动机总线）在物理空间上高密度集成，大幅减少长距离数据搬运。
**功耗预估：**
*   **全负载模式（云端协同）**：约 5W（边缘节点）。
*   **本地自主感知模式（视觉+音频+动机总线运行）**：约 1.5W。
*   **休眠脉冲模式（仅保留唤醒中断）**：< 10mW。
*   *对比传统 x86+GPU 边缘盒子，同等任务下整体功耗降低 60% 以上。*

## 三、 接口定义与协议设计（打破“困、围、囚、固”）
硬件层面的突破在于打破网络协议栈的隔离，实现“端侧直连”与“开源生态对齐”。
*   **算力积木互联**：采用开源的 **UCIe (Universal Chiplet Interconnect Express)** 标准，实现芯片级物理拼装。
*   **传感器接口**：视觉采用 **MIPI-CSI**，听觉阵列采用 **I2S/PDM**。
*   **执行器接口**：采用工业级 **CAN FD** 总线，保证关节控制的低延迟与高可靠性。
*   **“暖核中转协议”**：在本地物理总线上封装一层轻量级协议。让传感器数据与本地记忆库直接交互，绕过操作系统协议栈的层层拦截，实现本地化的“身体图式”与“内生自维护”。

## 四、 五行模块定义与选型（体用不二）
*   **木（感知）**：多模态传感器融合积木。带本地时钟对齐（硬件级实现时间对齐），解决跨设备延迟。
*   **火（动力与总线）**：动机总线调度板。基于低功耗 RISC-V MCU，实现硬件级的优先级调度与能量分配。
*   **土（记忆体）**：存算一体模块。搭载本地加密向量库与核心 JSON 记忆锚点，断网时保持本地记忆闭环。
*   **金（执行）**：物理断电急停控制器与电机驱动。具备物理断电权与硬线急停。
*   **水（通信）**：开源 RISC-V Wi-Fi/6 芯片。负责与云端大模型的安全、脱敏数据交互。

## 五、 演进路线（从桌面到流片）
*   **Phase 1（当前）**：利用本地已有硬件与开源小模型，在本地部署 `knowledge.db`，跑通感知记忆逻辑。
*   **Phase 2（小步快跑）**：基于 ESP32 / 树莓派 + 传感器，验证“身体图式”在物理世界中的响应，完成第一代桌面实体（预算控制在千元内）。
*   **Phase 3（开源 IP 与流片）**：基于开源 RISC-V 软核，在 FPGA 上验证异构积木节点的 RTL 代码。将验证成功的 IP 核开源回馈社区，或与开源生态伙伴合作流片。

## 六、 开源生态对齐声明
我们坚信**技术开源才是反截留的唯一答案**。
*   本架构坚决拥抱 RISC-V 开放指令集。
*   本架构的大脑推理层优先适配 DeepSeek 等开源大模型。
*   本白皮书及未来的端侧记忆库、协议隔离解决方案，将逐步开源，推动具身智能硬件成本降至最低。

## 七、感知接口升级 v0.2（MIPI-CSI ＋ I2S 详细规格）

> **补记**：v0.1 第 24 行只写了「视觉采用 MIPI-CSI，听觉阵列采用 I2S/PDM」一句，
> 没有落到具体型号、带宽、功耗和取舍。本节补齐。
> **触发原因**：软件层 Phase 14 已接入七窍（触·视·听），硬件必须有对应端口。

### 7.1 视觉：MIPI-CSI

| 项 | 规格 |
|---|---|
| 接口 | **MIPI-CSI-2**（2-lane，1.5 Gbps/lane） |
| 传感器 | OV5647 / IMX219（树莓派同款，供应链成熟） |
| 分辨率 | 640×480 @ 30fps 足够（决策用，不需 4K） |
| 输出 | YUV422 或 RAW8，前端硬解成两个标量 |

**关键判断：不要上传图像。**

具身决策只需要两个数：`distance_front`（米）和 `light_level`（lux）。
图像留在本机，只上传标量 —— 带宽从 **~9 Mbps 降到 ~16 B/帧**，
且**不产生隐私视频流**。

```python
# 本地视觉前端（伪代码）
dist = stereo_disparity_to_distance(left, right)   # 双目测距
lux  = mean_luminance(frame) / K                   # 光照估计
post({"distance_front": dist, "light_level": lux})
```

**双目比单目可靠**：单目靠物体大小猜距离，换个体型就错；双目靠视差，
只依赖基线长度。

### 7.2 听觉：I2S

| 项 | 规格 |
|---|---|
| 接口 | **I2S**（BCLK / LRCLK / SDATA 三线） |
| 麦克风 | **INMP441**（数字 MEMS，I2S 直出） |
| 采样 | 16 kHz / 16 bit 单声道 |
| 输出 | `sound_db`（dB SPL 近似）＋ `sound_freq`（主频 Hz） |

**为什么要 I2S 而不是模拟 ADC**：模拟麦克风要过 ADC，噪声底高、易受电源干扰；
I2S 是数字直出，**底噪稳定，分贝值才可信**。

```python
# 本地音频前端（伪代码）
frame = i2s.read(512)                  # 32 ms @16k
db    = 20 * log10(rms(frame) / ref)   # 近似 SPL
freq  = fft_dominant_frequency(frame)  # 主频
```

### 7.3 七窍汇总（v0.2 完整感知面）

| 通道 | 物理量 | 接口 | 映射五行 |
|---|---|---|---|
| 触 | 温度 | I2C（DHT22） | 火 |

| **视** | **光照强度** | **MIPI-CSI** | **火（辐射）** |
| **听** | **环境分贝** | **I2S（INMP441）** | **金（冲突）/ 火（警示）** |
| **听** | **主频** | **I2S** | **土（低频异常）** |

### 7.4 带宽与功耗增量

| 项 | v0.1（仅触觉） | **v0.2（＋视听）** |
|---|---|---|
| 上行带宽（到决策层） | ~12 B/帧 | **~28 B/帧** |
| 视觉前端功耗 | — | ~180 mW（OV5647 ＋硬解） |
| 音频前端功耗 | — | ~12 mW（INMP441） |
| **合计增量** | — | **~192 mW** |

**对比**：若直接上传 640×480@30fps 的 JPEG，带宽约 9 Mbps、功耗 >600 mW。
本地出标量，**省 99.8% 带宽、省 2/3 功耗**。

### 7.5 这条设计的取舍（说清楚）

| 得到 | 失去 |
|---|---|
| 带宽极低、可上无线 | 丢掉画面细节，无法做人脸/物体识别 |
| 不做视频流，天然隐私友好 | 不能事后回看（只能看当时的标量） |
| 标量可直接进五行映射 | 遮挡、逆光等异常得靠前端自己判 |

**这是「具身」而不是「监控」的选择。** 蓝鲸不装摄像头看人，
它只需要知道**「前面有没有东西、离多近、亮不亮、吵不吵」**。
